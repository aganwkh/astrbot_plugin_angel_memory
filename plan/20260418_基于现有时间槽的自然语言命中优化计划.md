# 20260418 基于现有时间槽的自然语言命中优化计划

## 背景

本次需求的边界非常明确：

1. 不改现有时间槽枚举。
2. 不改现有时间槽到时间窗的定义。
3. 只优化“自然语言如何命中现有时间槽”。
4. 优先复用现有 `time_intent / normalized_time_range / build_time_filter_payload / time_diagnostics`。
5. 必须保证一旦选中合法时间槽，后续检索链真正吃到这个时间窗做硬过滤。

结合当前代码，时间链路已经具备可复用骨架，问题主要在“时间槽分类入口不稳”和“follow-up 继承缺位”，不是底层没有时间过滤能力。

## 本次硬约束

1. “统一时间槽目录”只能是现有定义的只读聚合视图，用于统一读取和校验，不能成为新的 source of truth。
2. 模型必须是唯一的时间槽分类入口；程序不得再用短语规则决定最终时间槽。
3. 模型时间槽分类只能用于 recall/review 类查询，以及低信息 follow-up；不得对普通闲聊全局启用。
4. 最终合法时间槽一旦产出，无论来源是 `model_classifier` 还是 `followup_inherit`，都必须直接驱动 `strict_time_recall = true` 与 `time_filter` 透传，不能再被原始短语门控二次否决。
5. follow-up 槽缓存必须带短 TTL，且缓存键不能过粗，避免跨语义边界误继承。
6. provider 不可用时，允许继承已缓存的合法槽，允许降级为空，但不允许 silently 回退到规则分类。
7. `confidence` 不能只是日志字段；当置信度低于阈值时，模型应优先输出 `abstain = true`，程序不得把低置信分类直接当最终时间槽使用。
8. 模型输出必须严格结构化解析；若返回非 JSON、字段缺失或解析失败，一律按 `abstain` 处理，不允许回退到规则主判。
9. 验收口径必须是固定输入 -> 固定时间槽 -> 固定 `time_filter` 透传断言，不能使用“命中率明显提升”这类不可回归验证的表述。

## 实现目标

在不改动现有时间槽定义的前提下，实现一条单轨链路：

1. 先读取“现有合法时间槽集合”。
2. 模型作为唯一分类器，从现有槽中选择一个最合适的时间槽，或显式 `abstain`。
3. 程序校验模型输出是否合法。
4. 复用现有时间窗映射，生成 `normalized_time_range / start_ts / end_ts`。
5. 把时间窗硬透传到检索层。
6. 对低信息 follow-up 支持继承上一轮模型已命中的合法时间槽。
7. provider 不可用且无法继承时，明确降级为空结果，不伪造规则命中。

## 实施方案

### 阶段一：抽出“现有时间槽目录”和统一解析入口

涉及文件：

- `core/utils/time_diagnostics.py`

计划改动：

1. 把当前分散在 `TOOL_TIME_RANGE_SPECS`、`intent_specs`、“上周X”规则里的现有定义整理为统一的内部目录构建函数。
2. 这个目录只做“集中读取现有定义”的只读聚合视图，不新增、不删减、不改名，也不能反向替代原有定义位置。
3. 新增统一入口，支持：
   - 根据自然语言做现有规则识别
   - 根据 `normalized_time_range` 反查并构建 `TimeIntentDiagnostic`
4. `tool_time_range_to_intent()`、`analyze_time_intent()` 继续保留，但职责收敛为：
   - 统一槽目录读取
   - 合法性校验
   - 按槽反构建 `TimeIntentDiagnostic`
   - 调试辅助
5. 不再让规则链直接决定主路径最终时间槽。

原因：

- 现在并不是所有合法槽都能通过 `tool_time_range_to_intent()` 反解，例如 `recent_context`、`earlier_context`、`last_time`、`last_weekday_x`。
- 如果模型只输出 `selected_time_slot`，就必须有一条“从现有槽反构建现有时间窗”的统一入口，否则会被迫再手写一套映射，违反本次约束。

### 阶段二：增加“模型主导的时间槽分类层”

涉及文件：

- `core/utils/time_diagnostics.py`
- 可能新增一个轻量辅助文件，例如 `core/utils/time_intent_classifier.py`

计划改动：

1. 新增模型主导的时间槽分类层，模型是唯一分类器，返回结果最终落到现有 `TimeIntentDiagnostic`。
2. 该分类层只允许在两类场景触发：
   - recall/review 类查询
   - 低信息 follow-up
3. 普通闲聊、普通陈述、非回忆型请求默认不触发时间槽分类。
4. 模型输入只包含：
   - 当前用户输入
   - 必要的最近上下文
   - 当前时区和时间基准
   - 当前合法时间槽列表
   - 可选的上一轮已命中时间槽
5. 模型输出限定为结构化结果：
   - `selected_time_slot`
   - `confidence`
   - `reason`
   - 可选 `inherit_previous`
   - `abstain`
6. 程序侧必须做合法性校验：
   - 是否属于当前合法时间槽集合
   - 是否为空
   - 是否可被现有映射函数构建成有效时间窗
7. `confidence` 需要作为业务门槛参与决策，不只是调试字段：
   - 低于阈值时，模型应优先输出 `abstain = true`
   - 即使模型返回了合法槽名，若置信度低于阈值，程序也不得直接采纳为最终时间槽
8. 模型输出必须严格结构化解析：
   - 非 JSON
   - 字段缺失
   - 字段类型错误
   - 解析异常
   以上情况一律按 `abstain` 处理。
9. 校验失败或解析失败时按 `abstain` 处理，只允许走 follow-up 继承或空结果降级，不再回退为规则分类主路径。

调用策略：

1. recall/review 与低信息 follow-up 直接进入模型分类。
2. 模型输出合法槽时，直接进入程序校验和时间窗映射。
3. 模型低置信、解析失败、字段非法时，统一等价于 `abstain`。
4. 模型 `abstain` 时，只允许尝试 follow-up 继承。
5. 如果当前没有可用 provider：
   - 先尝试 follow-up 继承
   - 无可继承槽时明确降级为空
6. 不允许 silently 回退到规则分类。

### 阶段三：补 follow-up 时间槽继承

涉及文件：

- `main.py`
- `tools/core_memory_recall.py`
- 可能补充到插件实例或 `PluginContext` 的最小会话缓存

计划改动：

1. 新增最小会话级缓存，值只保存：
   - 上一轮模型已校验通过的 `normalized_time_range`
   - 对应 `TimeIntentDiagnostic`
   - 更新时间
2. 缓存需要带短 TTL，默认按“短时追问窗口”设计，避免跨较长对话间隔误继承。
3. 缓存键不能只用过粗的全局会话标识；需要至少绑定当前 recall 语义边界，避免不同话题或不同检索意图之间串槽。
4. 继承条件按本次需求落地：
   - 上一轮已有合法时间槽
   - 当前输入信息量很低
   - 当前轮没有更强的新时间锚点
5. 继承成功后，仍然要走统一的合法性校验和时间窗映射，不能直接跳过。
6. 继承结果要同时写入诊断日志，明确区分：
   - `source=model_classifier`
   - `source=followup_inherit`

说明：

- 这里新增的是“上一轮模型成功结果缓存”，不是新时间枚举。
- 缓存只承载现有时间槽，不会改变时间槽语义。

### 阶段四：把增强后的时间意图稳定透传到检索硬过滤

涉及文件：

- `main.py`
- `core/deepmind.py`
- `core/services/retrieval_service.py`
- `tools/core_memory_recall.py`

计划改动：

1. 在入口统一产出最终 `time_intent` 和 `time_filter`。
2. 只要 `selected_time_slot` 经过合法性校验并成功映射为时间窗，无论来源是 `model_classifier` 还是 `followup_inherit`，都必须直接令：
   - `strict_time_recall = true`
   - `time_filter.matched = true`
   - 下游检索收到该 `time_filter`
3. `main.py` 的原始聊天召回门控必须服从最终结果，而不是再以短语命中与否进行二次否决。
4. 需要去掉“模型已选中合法槽，但又被原始 recall phrase/短语门控重新置回 false”的路径。
5. `DeepMind` 检索入口沿用现有 `recall_policy`，但确保模型分类后的最终结果写入其中。
6. `core_memory_recall` 解析时间来源时，只接入“模型分类结果 / follow-up 继承结果”，并把最终时间窗传给 `memory_runtime.comprehensive_recall(..., time_filter=...)`。
7. 明确禁止出现“日志里已经选中了槽，但下游检索没吃进去”的情况。

### 阶段五：provider 不可用时的降级策略

涉及文件：

- `main.py`
- `core/deepmind.py`
- `tools/core_memory_recall.py`

计划改动：

1. 若当前轮模型可用：正常执行模型分类。
2. 若模型不可用但上一轮有可继承槽：允许走 follow-up 继承。
3. 若模型不可用且无可继承槽：明确降级为“无时间槽”，不伪造规则命中。
4. 诊断日志中必须明确区分：
   - `classification_status = classified`
   - `classification_status = inherited`
   - `classification_status = abstained`
   - `classification_status = low_confidence_abstained`
   - `classification_status = parse_failed_abstained`
   - `classification_status = provider_unavailable_empty`
5. 不允许 silently 回退到规则主判。

   - 模型低置信时不会直接采纳合法槽，而是按 `abstain` 处理
   - 模型输出非法槽时会拒绝，且不产生伪时间窗
   - 模型返回非 JSON、字段缺失或解析失败时按 `abstain` 处理
   - 模型 `abstain` 时不会退回规则分类
   - follow-up 短句会继承上一轮模型已命中的时间槽

3. 实现完成后同步更新 `metadata.yaml` 的 `version`。

## 风险与注意事项

1. 不能把“统一目录”做成新定义源，必须只是现有定义的程序化只读收敛。
2. `last_weekday_x`、`recent_context`、`earlier_context`、`last_time` 这类槽当前不是纯工具槽，实施时最容易被漏掉。
3. 模型分类只能做“现有槽分类”，且只能用于 recall/review 与低信息 follow-up，不能让它变成普通对话的全局时间解释器。
4. follow-up 继承必须有 TTL、缓存键收窄和覆盖条件，避免把旧槽错误粘到新问题上。
5. provider 不可用时只能继承或降级为空，不能回退到规则主判，否则会重新形成双轨链路。
6. 最终合法槽的效力必须高于原始短语门控，不允许出现“模型/继承已产出合法槽，但 strict_time_recall 仍为 false”的回归。
7. 如果不把 `confidence` 作为采纳门槛，模型会把边界模糊输入硬塞进某个槽，导致错误硬过滤；因此低置信必须显式 `abstain`。
8. 如果不把结构化解析失败统一视为 `abstain`，实现时很容易偷偷回退到规则主判，重新破坏单轨方案。

## 验收标准

1. 现有时间槽名称、数量、时间窗定义保持不变。
2. 模型输出只能命中现有合法时间槽。
3. 固定输入 `"上周四那个事你还记得吗"`，当模型输出 `selected_time_slot = last_weekday_3` 时，必须稳定映射出对应时间窗，并断言 `time_filter.matched = true` 且实际透传到下游检索调用。
4. 固定输入 `"昨晚一起聊的那个"`，当模型输出 `selected_time_slot = last_night` 时，必须稳定映射出对应时间窗，并断言 `strict_time_recall = true` 且 `time_filter` 被实际传入检索层。
5. 固定输入 `"今天凌晨那个"`，当模型输出一个合法现有槽时，必须断言该槽经现有映射生成固定 `start_ts/end_ts` 后被下游消费。
6. 模型输出非法槽时，必须被拒绝，且不产生伪时间窗、不触发规则分类兜底。
7. 模型输出合法槽但 `confidence` 低于阈值时，必须按 `abstain` 处理，不得直接生成最终时间窗。
8. 模型返回非 JSON、字段缺失或解析失败时，必须按 `abstain` 处理，不得触发规则分类兜底。
9. 模型 `abstain = true` 时，若无可继承槽，必须保持“无时间槽”结果，不走规则分类兜底。
10. 在 follow-up 用例中，第一轮模型命中合法时间槽后，第二轮固定输入 `"你再想想"` 必须在 TTL 内稳定继承上一轮时间槽，并断言透传后的 `time_filter` 与上一轮时间槽一致。
11. 一旦最终合法时间槽来自 `model_classifier/followup_inherit` 任一来源，都必须断言 `strict_time_recall = true`，且不能被原始短语门控重新置回 false。
12. 实现完成后，新增回归测试覆盖上述固定输入、固定时间槽、固定 `time_filter` 透传断言。

## 建议执行顺序
